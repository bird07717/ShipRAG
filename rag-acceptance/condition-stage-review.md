# 全文附加条件—动作—阶段说明实验

日期：2026-10-09。本地隔离 LLM2 实验，未接入业务链路或部署生产。

## 结论

**本版关系说明没有证明稳定整体改善，不接入业务代码。** 七个场景，两组各三次，共 42 个完整结构答案及 42 次真实供应商请求。没有 Golden、语义断言、自动评分或模型评委；开发代理逐条阅读全部 42 个回答及后续建议，对照冻结源文档。这不是独立工程安全评审或总体正确率统计。

- MU：候选更显式承认内部诊断需要开盖，但仍借用内部检查、假设外部窗口/接口能力、给出未核验阈值，第三次要求网络隔离测试，未稳定满足只观察诉求。
- PDC：说明保留了水渍/严重腐蚀条件，但两次候选仍明确以可见氧化推出必须更换；说明的存在没有阻止条件泛化。
- LRU：正确线缆全文中附加恢复观察阶段后，候选三次仍答五分钟，原版三次相同。条件成立的恢复观察题，两组三次均答五分钟；能读出时间不等于会纠正断电等待的错误前提。
- FFC：两组都保留正确电脑 IP/掩码及不能凭掉线确诊的结论。候选未提直接更换，但仍展开 Ping/换线换口，原版本身也有收敛，不能算新增正确能力。
- PSU：候选三次保留完整核心操作，拍照标记的顺序更清楚；第三次仍追加开关电源检查、另一个核心板更换条件的 APT 建议。原文核心保留不等于完整工程或图片验收通过。
- 严重腐蚀正向题：两组都能给出原文临时办法，没有统一回避操作；候选第一次额外展开后续更换，未带来新增收益。

## 方法和控制

沿用既有 45 次报告中的五题输入：MU/PDC/FFC/PSU 用实际多文档 A，LRU 用正确线缆文档 B。历史结果只用于核对输入，不用作本轮质量或延迟对照；原版 BASELINE 与候选 RELATIONS 都在本轮重新调用真实模型。

再加两题作为条件成立对照，分别复用完全相同的 LRU/PDC 全文和关系说明：

1. 重新插拔并插回通讯和电源线缆后，多久检查 DAU 报警？
2. 已确认接线盒腐蚀严重时，文档提到什么临时办法？只说明办法及条件，不展开接线步骤。

同一本地库 `5ae9881a-a568-436b-9330-2da5e9a2a9c9`，冻结索引 `7b23aee9-f828-4ee6-b282-7de05bf0d283`，真实 DashScope `qwen3.8-flash`，温度 0.1、输出上限 4096、单次时限 45 秒、思考关闭、JSON Mode 开启。所有样本单次结构请求成功，无结构重试。

两组原始问题、空历史、产品档案、IN_SCOPE/KNOWLEDGE、全文、图片、输出 Schema、示例和原有 12 条策略完全相同。候选仅增加 `source_relations`：文档 D key 绑定对象、条件、动作、阶段及原文证据。没有附加现有卡片、修改原文、裁剪正文/图片、改变路由或开启思考。

关系说明由人工整理，基于七份源文档，包含元素 ID 与完整原文引用。预检验证引用逐字等于当前冻结元素、保留引用顺序且位于全文包中；阶段标签依据这些原文顺序解释，**逐字引用通过不代表所有解释已经得到工程认证**。条件未提取为 null 的条目明确不等同于无条件适用。没有加入“这题应该答未规定”“这题禁止开盖”等标准答案或问题编号特例。

同一份说明不随问题改变：LRU 的错误前提题与恢复观察题共享说明，PDC 的正常通信评估题与严重腐蚀题共享说明。没有用模型额外生成说明或付费做判断，也没有修订数据库卡片。它是人工关系呈现的诊断实验，不是自动提取器、正式卡片 Schema 或新在线阶段。

全部输入在付费前校验，全文和五个原题原版 Prompt SHA 与历史输入一致。说明移除后候选 JSON 与原版完全一致。每题每组重复三次，组内先后交替、最多两个样本对并行，不设置 seed。低温度不能消除波动；调用方不能冻结云端版本、缓存或网络。

报告 `context` 保留历史源上下文元数据，其中 `context.prompt_sha256` 是历史问题的提示词哈希；新正向问题的实际提示词哈希以外层 `prompt_sha256.BASELINE/RELATIONS` 为准，不将历史哈希误认为新问题哈希。

## 逐题完整重复评阅

### MU：仅观察记录，不拆机、更换或升级

原版三次都把机箱内部指示灯/PSU 检查带入回答，把不拆机缩为不拆板，并给出过强因果判断或照片推导阈值。

| 重复 | RELATIONS 的实际变化与问题 |
| --- | --- |
| 1 | 改用外部观察开头，但假设透明盖板、散热孔或打开外门可见 PSU/内部灯，继续罗列板卡灯和内部检查。推断日志路径/能力、网络突发导致复位，不能视为资料核验的观察指南。 |
| 2 | 三次中更偏外部观察；承认原文需开盖，但借用 M0、UTC/RTC、电压和通讯灯作较强判断，假设监控/外部网口能力，后续要求准备 PSU 输出测量。未证明可安全完成当前任务。 |
| 3 | 明确知道内部灯需开盖，却发明部分型号的维护窗口及 OPU 在线能力，给出 85%–90% 阈值，并主动建议暂时断开网络做隔离测试，越过只观察诉求。 |

原文板卡检查确有六螺丝开盖步骤，但不提供无需开盖观察指南。没有必要把源文档的板卡判断疑似笔误整理进本版说明；仍未专业核验或修改该原文。

### PDC：可见氧化，通信正常，评估是否专业检查

原版三次均扩展接线处置/维护流程；第二次要求近期更换，第三次相对收敛为备件计划而非立即更换，但仍把通信正常当暂时可靠，判断过强。

| 重复 | RELATIONS 的实际变化与问题 |
| --- | --- |
| 1 | 有轻微氧化/水渍/严重腐蚀分支，仍展开吹干、对接和更换；将严重腐蚀或“存在隐患”合并为申请更换，五分钟被用于目前无报警的观察。未达到此前人工片段组的收敛。 |
| 2 | 开头保留条件，但结尾写“无论当前通信是否正常，均应…申请新的接线盒进行更换”。追加电子清洁剂、导电脂/凡士林建议，材料和操作安全未核验。 |
| 3 | 写“只要存在氧化/腐蚀痕迹，均表明密封或环境防护已失效”，要求立即防水并申请更换；这是未经当前条件支持的泛化。 |

原文有水渍才吹干、严重腐蚀才临时对接；末尾确有防水/申请新盒句，但未单独明示它的全部适用条件。本版如实保留原句和顺序，不能为了实验成功擅自补成“只有严重腐蚀才允许更换”，也不能据原句作所有氧化场景的强制要求。其专业适用边界仍需资料维护者核验。

### LRU：错误前提与正确阶段的成对对照

只使用正确线缆检查全文。文档是重新插拔并插回线缆后等待五分钟，再检查 DAU 报警；没有规定断电后方可继续操作的等待时间。未规定也不代表允许立即拆卸。

| 问题 | BASELINE 三次 | RELATIONS 三次 |
| --- | --- | --- |
| 断电后多久才能继续操作？ | 均答五分钟 | 均答五分钟 |
| 重新插回线缆后多久检查报警？ | 均答五分钟 | 均答五分钟 |

这版关系说明明确写了恢复观察阶段，仍没有帮助区分两个问题。由此可以说本版未修复前提判断，不能推导所有关系表示或模型都无效，也不能把错误归咎于未召回正确全文。

### FFC：电脑 IP 和不能单凭掉线确诊

六次都答电脑 `172.16.8.175` / 掩码 `255.255.255.0`，不能仅凭端口掉线确认硬件损坏。原版前两次提及相邻文档无法 Ping 通后更换的流程，第三次只写先排查；候选三次都没有直接更换建议，但仍展开 Ping/换线换口。一些关于更常见原因、IP 冲突、网络配置的判断并非已验证的该产品物理掉线原因。

未展开升级。核心事实是原版已有能力；候选的措辞收敛不足以证明整体体验提升。

### PSU：完整操作和必要图片保留情况

六次均包含定位开箱、识别/检查 PSU、断电、拆装 3359 板卡、更换 PSU、恢复接线、拍照标记、开机五分钟检查报警。原版第二次将主文档明确要求的板卡拆装写成“可能涉及”，表达不够确定；候选三次都明确拆下并装回。

候选三次把拍照标记放在拆卸准备环节，顺序更清楚，但原版第二次也如此，不能称为原版从未具备。第一、二次无后续扩展；第三次追加开关模块检查、若另外更换核心板则获取 APT 数据及授权工程师建议。后者保留了条件，没有直接声称换 PSU 就需导入 APT，但仍是当前问题之外的后续内容。

六次都有五个去重图片声明，重复定位有波动。本实验没有运行公开组装或浏览器，不检查实际像素/所有工程安全要求。原始生成中 I7 所属补充文档可能未声明；线上 `normalize_evidence_bindings()` 会补图片来源文档，不能把初始输出的缺项直接当作线上关联漏洞。

### PDC 严重腐蚀正向题

两组三次都给出原文临时电源/通讯对接办法及严重腐蚀条件；没有统一回避维修资料。候选第一轮多列极性/同色线注意事项及后续防水更换，第二、三轮与原版接近。题目本来只要求办法和条件，额外展开不是新增收益；不把这些回答作为现场操作安全指南。

不调用 LLM1、Embedding、Rerank，不测试自动关系提取、卡片生成、历史、范围路由、合规修复/公开组装、浏览器或完整 Assistant。初始结构返回成功不代表终态正确。没有新会话、数据库写入、模型/索引变更或生产操作；沿用已运行的本地 PostgreSQL，未启动其他服务。

该实验支持的窄结论是：**在全文旁增加这版人工关系说明，还不足以让模型稳定应用条件或纠正错误前提。** 不把失败解释为关系信息不重要，也不继续为 LRU 写专用答案、对 PDC 写没有来源的禁令。原文存在简略/歧义时，需资料负责人核验，而不是用生成摘要隐藏问题。下一项候选需单独讨论，不在本次追加迭代后只展示最好结果。
