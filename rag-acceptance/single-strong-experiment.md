# RAG 首轮单强直达：本地实验（2026-09-11）

## 结论

建议将“最强 Chunk 明显领先”作为 **RAG 首轮选文档的保守补充规则**，先做影子记录与真实模型验证，不直接全局降低聚合阈值。不引入 Support 的 Profile、标准问题、标签或路由；本次没有修改在线实现、配置、索引或生产服务。

当前证据支持继续验证 `best >= 0.85` 且 `best - other_document_best >= 0.18`，不构成上线阈值已校准的结论。它只补救少数不必要的澄清，不能解决全部首轮命中问题。

## 实验范围与判定

- 本地 PostgreSQL 只读事务，历史真实 SiliconFlow `Qwen/Qwen3-VL-Reranker-8B` 分数回放；没有重新调用 Embedding、Rerank、LLM，没有执行 HTTP 全链路 A/B。
- 历史时间为 2026-09-01 至 2026-09-08；535 条已完成 RAG CHAT、无父 Trace 的真实模型记录中，109 条无法证明为会话首轮而排除。
- 纳入 426 条：通过首个 Assistant 消息序号，或 Golden 请求 ID 与当前用例首问一致证明首轮，并要求 `ALIGNING`。其中 423 条 Rerank 成功、3 条降级；新增直达拒绝降级分数。
- 同一索引；每条保留的重排候选均为 Top 5。按归一化问题取最新记录后，只有 **44 个不同问题**，不得把重复 Golden 运行算作独立样本。
- 基线用当前代码、当前本地阈值重算文档聚合，并保留现有标题匹配直达；不是重新生成历史最终回答。聚合直达和标题直达已解决的问题不计为新增收益。
- 新规则比较各文档最强块，竞争者必须来自另一文档；至少观察到两个文档。只接受成功 Rerank 的原始有限 `[0,1]` 分数，不对 logits 做临时归一化，不将相关分数解释为概率。
- 正确性标签来自当前 Golden Set；只有期望标题键唯一对应一篇文档的 `EXACT` 才记为“唯一目标相符”。`ANY_OF` 或标题键对应多篇文档单列为“歧义兼容”，不能证明直接交付合理；无标签样本不记正确。

## 对比结果

44 个不同问题的当前确定性基线：22 个直达（19 个聚合、3 个标题匹配）、6 个澄清、16 个 NO_MATCH。包含范围外问题，因此直达比例不是正确率；NO_MATCH 后续也可能由目录 LLM 继续回答。

| 0.90 / 0.20 | 0 | 0 | 0 |
| 0.85 / 0.18 | 1 | 0 | 9 |
| 0.80 / 0.15 | 1 | 0 | 9 |

本批标签没有发现新增错选目标，但数据量小、用于选择阈值且无独立留出集，不能宣称误命中率为零。去重样本有 5 个范围外问题，新规则均未触发；没有新噪声 Golden 样本，不能替代噪声回归。

### 关键案例

| 问题 | 最强块 / 其他文档最强块 | 当前结果 | 实验发现 |
| --- | --- | --- | --- |
| LRU怎么升级版本 | 0.8576 / 0.6129 | CLARIFY | 0.85/0.18 可选中《如何升级LRU》，9 次历史运行方向一致，但只算 1 个问题。 |
| 船名在哪里修改 | 0.6958 / 0.0523 | CLARIFY | 真正只命中一个块的例子；须降至 0.65 档才直达，暂不足以支持全局放宽。 |
| 蓄电池组怎么更换 | 0.6828 / 0.2878 | CLARIFY | 0.65 档新增收益；应补充电池对象混淆题验证。 |
| 怎么查看U盘的格式 | 0.6199 / 0.0256 | NO_MATCH | 0.60 档新增收益；分差大不等于绝对证据强。 |
| MU报警了怎么处理 | 0.6186 / 0.4983 | NO_MATCH | 0.60 档会自动选“排查”文档；Golden 为 ANY_OF，无法证明无需澄清排查/更换意图。 |

LRU 问题不是“只召回一个块”：目标有 2 块，聚合分 1.6074；聚合第二名为 1.0211，比例约 1.57，小于当前 1.8，所以进入澄清。最强块方案补充了聚合排名的不足，而不是证明所有单块候选都应直达。

该问题最强块同时标记 `suspected_incomplete=true`、`FOLLOWED_BY_IMAGE`。**单块用于选文档，不是只返回这一个块**；实际交付必须沿用完整文档/步骤及关联图片读取，避免漏图、漏前置条件和步骤。

另有“FFC600电池组怎么更换”“怎么屏蔽DC24V解决绝缘低问题”“绝缘低报警怎么解决”三个问题，期望文档没有进入已保存的重排 Top 5。仅改最终直达阈值无法恢复这些目标；应进一步检查原始召回及重排输入，区分未召回与被排序淘汰，不能根据 Top 5 就断定向量召回失败。

## 建议的后续实施顺序

1. **仅在 RAG 层新增可关闭的首轮补充分支**：无焦点、无待确认选择，输入门禁及现有确定性直达优先；成功真实 Rerank、原始分数尺度匹配、不同文档之间计算领先。共享 `doc_router` 也被 Support 使用，不能直接在共享策略上放宽。
2. **先影子记录，不改变回答**：记录拟选文档、最强块、跨文档第二名、分差、规则版本及当前路由。以 0.85/0.18 为待验证起点；模型、索引或候选数量改变后重新校准，只有一个候选文档时本实验规则不自动认定领先。
3. **独立补充验证题**：LRU 升级/更换、PDC/FFC 接线盒、AC/DC/电池保险丝、MU 排查/更换、单块完整/不完整、多对象/多意图、范围外及噪声。新增严格断言：明确问题应为直达且唯一文档正确；歧义题不得因宽松 ANY_OF 就被当成单强成功。题目不能全部使用本次调参样本。
4. **再处理 Top 5 缺失目标的问题**：对比 BM25/向量原始候选、重排输入与输出，实验候选文档多样性、适度扩大重排窗口及标题/正文信号；继续保持 RAG 与 Support 独立。
5. **真实 Assistant 全链路验证后才启用**：核验单文档正确率、歧义自动直达率、拒答边界、焦点及上下文版本、SSE 终态、来源与图片完整性，以及 p50/p95。沿用现有交付与状态更新路径，不增加接口，不改对接契约；保留关闭开关。

性能方面，新判据只做已有 K 个候选的分组比较，不增加模型调用；当前离线脚本另有排序。是否减少整体延迟取决于原分支：固定澄清本身已不调用 LLM，整篇文档交付反而增加读取和传输；本次没有测在线延迟或并发容量。
