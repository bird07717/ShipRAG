# 部分相关文档的回答体验实验（2026-10-08，本地）

## 结论与交付边界

两版 LLM2 提示词窄调整没有证明稳定改善，其中一版在 PDC 场景产生了更强的无条件更换要求。**不保留业务提示词修改、不建议部署候选版本**；`answer_generator.py` 已恢复到本轮实验前内容，LLM1、路由、检索、全文预算及公开协议均未修改。

保留真实问题、原始回答收集工具和本评阅记录。评阅由本次开发代理逐条阅读回答并对照本地源文档完成，不是独立工程专家认证，也不是正确率统计。没有将自动断言结果作为改善结论。

## 条件与方法

- 本地已上线、就绪的 VDR600 测试库；当前冻结索引 `7b23aee9-f828-4ee6-b282-7de05bf0d283`。未上传、重建、激活或修改任何文档。
- LLM 为数据库配置的 DashScope `qwen3.8-flash`；Embedding 为 SiliconFlow `Qwen/Qwen3-VL-Embedding-8B`，Rerank 为 DashScope `qwen3.7-text-rerank`。运行端点报告 REAL，实际调用真实供应商。不是生产验收。
- 6 个固定问题，包含一组两轮对话，因此每版 7 个完整 Assistant 轮次。基线、候选 A、候选 B 共 21 轮；各版使用新测试会话，问题不变。
- 候选 A：仅强化现有 `decision_policy` 第 4/5/10 条，说明任务/否定/假设优先、条件不能倒置、部分文档与通用分析可混合。
- 候选 B：在 A 上将同一任务边界加入初次生成及已有合规修复的 System Prompt。不增加模型调用、路由字段或结构化输出字段。
- 端到端候选/基线可能受到 LLM1 改写和检索波动影响，不能把一次差异全归因于提示词。
- 另做 4 组固定文档对照、共 8 次真实 LLM2 调用：对每组固定问题原话、相同有序文档上下文及空历史，比较原版与候选 A；绕过 LLM1 和检索，**这不是完整链路测试**。候选调用次序交替；文档只读，报告只保存上下文哈希/标识及回答，不保存全文输入。
- 另直接检查 2 次原版 LLM1 的问题改写：本次均保留 MU 的“尚未确认、不拆机”及 PDC 的“通信正常、无升级需求”。这不能证明之前某轮实际改写也一定正确。
- 原计划的 72 题全量 Golden 已按用户新指示中止，没有完整报告，不能声明全量通过；6 题最初已采集的完整响应仅作为基线原始数据复用，导入时丢弃全部断言得分。

## 核验到的文档事实与评测陷阱

- FFC 升级原文将**电脑地址**推荐为 `172.16.8.175`，随后登录指令使用 `172.16.8.100`。本轮最初增加的自动断言误用后者检查“电脑 IP”，已经撤销；不能把命中设备地址当作正确回答。
- PDC 接线盒原文有“如有水渍”和“如腐蚀严重”的处理条件；不能把完整故障处理流程自动推广为“通信正常且仅发现氧化就必须更换”，更不能由此推导“不需要专业评估”。
- LRU 线缆检查中的“等待 5 分钟”关联重新插拔后的报警检查；只出现同一个数值，不能证明模型回答了用户询问的同一阶段。
- 板卡诊断原文的核心板/底板指示灯描述存在疑似笔误。候选 B 提示核验，而基线直接解释为核心板故障；这是语料歧义，不能简单计入提示词提升。
- 文档里的账户、密码及实际服务凭据不进入本评阅记录；报告按本地诊断数据处理，不提交版本库。

## 保存的启发与判断修正

1. **原则正确不等于模型稳定执行。** 原版已经要求候选不是结论、设备/任务/阶段匹配和有界通用回答；两版强化同类规则没有证明收益，并出现退化。不能继续把“提示词里新增了边界”当作修复完成，也不能据此断言所有提示词调整都无效。
2. **文档正确、召回相关、当前适用是三个不同问题。** 同一设备的升级、维修或应急流程可以被正确召回，但其中事实只有在对象、触发条件及操作阶段匹配时才能用于当前结论。“尚未确诊”不是“已排除”；“通信正常”不能自动触发严重腐蚀的应急处理；同一个数值不能跨阶段迁移。
3. **错误不只来自 LLM1，也不能全部归咎于 LLM2。** 固定原话与文档的调用仍违反限制，证明下游也会出错；这类调用绕过了真实 LLM1，不能证明某次端到端改写无误。真实轮次须先查标准化问题，再查证据适用性，不能凭输出倒推唯一原因。
4. **回答更多不一定更有用，收紧更多也不一定更安全。** 用户问风险评估，展开维修步骤可能偏题甚至越过“不拆机”限制；但完全禁止推断、必须全条件确认或一律追问，也会损害解释能力和正常技术回答。目标是当前任务内的最小充分回答，不是统一变短或统一拒答。
5. **评测本身也需要核验。** 本次新增 IP 断言写错，已撤销。自动回归可检查稳定事实和工程契约，不能取代完整回答的条件/阶段核验；原版已成功的能力不得计为候选新增收益。没有独立工程复核时，不将涉及接线、带电测量或操作安全的建议标为已认证。

## 下一步设计方向（设计阶段记录；后续实验见下文）

同日已按下述方向执行合并重组实验，仍未证明整体体验改善，未接入业务代码。执行方法、重复回答与完整 Assistant 对照见 [第二次实验记录](context-reorganization-review.md)。以下保留当时的候选设计，不能当成已验证的修复。

### 保留架构，先定位再改动

- 保留双 LLM、唯一 `response_path`、既有检索/Rerank、有界完整文档及公开响应契约；不新增在线评判模型、任务状态机、长期记忆或问题文本特例。
- LLM1 继续负责独立请求、关系、范围与文档依赖，LLM2 继续负责证据选择和回答。先查失败轮次的 `resolved_question` 是否保留限制：若丢失，定位上游；若保留仍答错，优先实验回答阶段。当前不恢复双问题输入或新增约束字段；相关变更须另行验证 ADR-0030 的取舍，不能当作必然收益。

### 优先实验“替换与组织”，不继续叠加规则

- 首个候选仅重组技术 LLM2 已有的任务/证据适用性段落，将重复规则合并为一个短的判定顺序：以本轮任务及现场条件为边界；匹配事实的对象、触发条件和阶段；只输出当前问题需要的结论或行动。不是在原 12 条策略之外再加一套同义规定。
- 文档匹配可以是局部的：适用的事实照常使用，不适用的章节不强行展开；剩余部分沿用既有有界通用分析和 `DOCUMENT_AND_GENERAL` / `GENERAL`，不增加第三种路由或新输出字段。资料未提供某项规定时可以如实说明，并给出明确标为建议的专业判断，不能推导安全许可。
- 保留用户目标不代表接受问题中的所有前提。例如问“断电后要等几分钟”，资料若只写重新插拔后等待检查报警，应说明两者不是同一阶段，而不是为了直接作答强凑一个数值。先回答可核实的部分，再点明这一处必要差异；不扩大为每题都质疑用户。
- 不要求每个问题机械列检查清单或展示内部判断过程。完整操作题仍需完整步骤和必要图片，不能为了改善评估题而损害操作题；是否追问沿用“缺失条件是否改变关键结论”，不是只要条件不完整就阻断回答。
- 本次未检验“合并/重排策略”的独立效果；它只是减少指令重叠的一项假设，不是已找到根因。文档过长、输出示例偏向文档答案等也只能列为待测因素，不能同时改动或写成确定原因。不新增自动截文、事实抽取或适用性硬门禁。

### 用小实验决定是否保留

1. 同库、同冻结索引、同模型配置，以原版为对照；先固定失败问题和有序上下文，只改变一个提示词因素。固定输入只提高可比性，不能消除模型波动。
2. MU/PDC 等真实失败题与原本正常的局部参数、完整操作/图片、多轮纠正、混合回答一起评阅。每个关键场景每版至少重复 3 次，记录全部结果，不挑最好一轮；这是观察波动的初始样本，不是统计稳定性证明。
3. 逐条比较任务与限制、事实适用条件、实际帮助、未请求操作及过强结论；如输出断言与原文冲突，先纠正评测，不据错误期望修改回答。涉及工程安全的争议标为待专业核验。
4. 只有失败模式出现可重复改善、正常题未见明显回退，才继续完整 Assistant 链路验证及 Golden 工程回归；出现新的严重约束违背或误导性操作时撤回候选。不得用总分增长掩盖高后果错误，也不为追求 100% 添加特例。

上述仅保存后续优化思路。本轮没有实施候选、再次调用真实模型或部署生产环境；已知错误仍未解决。长期评估约束见 [ADR-0035](../docs/ai/decisions.md)。

## 重复采集方法

`run_context_review.py` 只发送真实请求并保存完整回答/诊断，不包含质量断言、评分或模型评委。先后部署到不同的本地测试端口以免热重载混淆版本，并使用同一问题文件、知识库和模型。

```bash
.venv/bin/python rag-acceptance/run_context_review.py \
  --base-url http://127.0.0.1:<测试端口> \
  --kb-id <已上线且就绪的测试库ID> \
  --questions rag-acceptance/context-applicability-questions.jsonl \
  --label <版本标签> \
  --output rag-acceptance/reports/<实验目录>/<版本标签>.json
```

工具沿用既有安全凭据加载和 SSE 收集函数；创建隔离测试用户及会话，会调用付费真实模型，不改变索引、模型配置或其他用户数据。新采集结果逐轮落盘，接口失败也记录，不静默删除失败问题。
