# ADR-0005：模型密钥存储和使用边界

- 状态：接受
- 日期：2026-08-17

## 背景

V1 使用全局 Model Config，并需要管理不同云厂商的 API Key。将明文密钥直接存入 `model_config.api_key` 会使数据库查询、后台响应、日志、Trace 和备份泄露风险显著增加。

项目没有用户登录，但这不降低云模型凭据的保护要求。

## 决策

1. 数据库存储 `api_key_ciphertext`、`api_key_nonce` 和 `api_key_key_version`，不存可读明文列。
2. 应用使用认证加密（M1 默认实现选用 AES-256-GCM 或由部署平台 Secret Manager 提供等价能力）。
3. 主密钥只来自进程环境或部署 Secret，不写数据库、配置文件、Git、日志和 Trace。
4. 密文必须包含或关联密钥版本，以支持轮换。
5. 普通 API 只返回：

```json
{
  "api_key_configured": true,
  "api_key_masked": "****abcd"
}
```

6. 完整密钥只在 Model Gateway 发起请求前的最小作用域内解密，不缓存到普通全局对象，不进入异常文本。
7. 创建/更新接口中的密钥字段为 write-only；省略表示保留原密钥，显式清除使用独立操作，避免 `null` 语义混乱。
8. Authorization、Cookie、API Key、签名 URL 查询参数、图片 Base64 默认加入日志脱敏规则。
9. 模型 `base_url` 必须使用 HTTPS（本地测试例外）并经过协议、主机和地址校验，生产环境应使用 Provider 白名单，防止 SSRF。
10. 备份包含加密密文，但主密钥必须采用独立备份与访问策略。

## 密钥轮换

M1 数据结构至少支持：

```text
ciphertext
nonce
key_version
```

轮换流程：

1. 部署新主密钥版本；
2. 新写入使用新版本；
3. 后台任务逐条解密并重新加密旧记录；
4. 验证所有模型连接；
5. 在回滚窗口后停用旧主密钥。

## 后果

### 正面

- 数据库、备份和只读管理查询不会直接暴露模型密钥。
- 密钥展示与更新语义明确。
- 为生产 Secret Manager 和密钥轮换留出接口。

### 代价

- 应用必须管理主密钥可用性和轮换。
- 丢失主密钥会使现有密文无法恢复，因此需要独立备份策略。
- 应用层加密不防御已经能够读取进程内存或主密钥的攻击者。

## 本地开发

- `.env` 可提供开发主密钥和非生产模型凭据，但不得提交。
- `.env.example` 只放占位符。
- 单元/集成测试默认使用 Fake Provider，不要求真实模型凭据。
